# QA-DMS User Manual
Website: https://qadms.online
English instructions and UI labels

## Sign in and identify your portal
Role: ALL ACCOUNTS
Path: Sign In
Open QA-DMS using the account issued by your administrator. Your role and organization determine which pages and records you can access.

1. Open https://qadms.online in your browser.
2. Enter your Email Address and Password, then select Sign In.
3. Check your name and role at the top. Faculty and staff use the User Portal; authorized administrators have management pages.
4. If you forget your password, follow the email recovery steps in the next section. Select Logout when finished, especially on a shared computer.

Remember: Personal passwords are not included in this manual. The presentation account list is provided separately.

## Forgot password: recover access by email
Role: ALL ACCOUNTS
Path: Sign in > Forgot password? > Email reset link
Use the email address registered to your QA-DMS account to request a password reset link.

1. Open https://qadms.online and select Forgot password? on the sign-in page.
2. Enter your registered Email address, then select Send reset link. The confirmation does not reveal whether an account exists.
3. Check your email inbox and Spam or Junk folder. Open the password reset email and follow its reset link.
4. On Set a new password, enter a New password that meets the displayed requirements. Re-enter it in Confirm password and select Reset password.
5. After the success message, return to sign in at qadms.online and use your new password. If the link is expired or invalid, request a new one.

Remember: Keep reset links private. If no email arrives, check the address you entered and contact your administrator to verify your account or email delivery. Never send your password by email.

## Dashboard and notifications
Role: USER
Path: User Portal > Dashboard
The dashboard highlights assigned work, submissions that need revision, request updates, and recent activity.

1. Open Dashboard from the sidebar.
2. Review Tasks needing action and Submissions to revise. Open the relevant task or submission for details.
3. Use My Accreditation Progress to review your own progress.
4. Open Notifications or the bell icon for updates. Use My Activity to review your account history.

Remember: Your personal submission progress may differ from the shared progress of the entire program or college.

## Organize your personal repository
Role: USER / ADMIN / ROOT
Path: My Documents
My Documents is the personal repository for each account. Administrators do not automatically have access to other users' private files.

1. Open My Documents. Select New Folder and enter a clear folder name.
2. Single-click to select an item; double-click to open a folder or file.
3. Select Upload to add a file to the current folder. Wait for the upload to finish before leaving.
4. Use search, file-type filters, and List or Grid view. Use the breadcrumb to return to a parent folder.
5. Open Shared with Me, Favorites, Recent, Requested Documents, or Recycle Bin as needed.

Remember: Use clear filenames and reporting periods. Moving a file does not submit it as accreditation evidence.

## Preview, download, and file actions
Role: USER / ADMIN / ROOT
Path: My Documents > File Actions / Preview
Open a file to read its current version and inspect its metadata and activity. Available actions depend on your access.

1. Double-click a file, or open its Actions menu and select Preview.
2. In Preview, use Download or Print when available. Download file types that do not support an inline preview.
3. Open Details & Activity to inspect version and activity information.
4. Use Rename, Move, or Delete when permitted. Recoverable deleted items appear in Recycle Bin.
5. Select Replace Version from Actions to upload a revised copy while retaining the document identity and version history.

Remember: Confirm that you selected the correct file before deleting or replacing it. Permanent deletion may be blocked for files referenced by accreditation evidence.

## Request access to documents
Role: USER
Path: User Portal > My Requests
My Requests is used to formally request documents or access. This is separate from submitting accreditation evidence.

1. Open My Requests and select Request Files.
2. Choose available documents and provide a clear justification. Follow the file limit shown in the request dialog.
3. Submit the request and monitor its status in the list.
4. Select View for request details. A Pending request can be cancelled when Cancel request is available.
5. After approval or fulfillment, check Requested Documents or the access granted to your account.

Remember: Pending means awaiting a decision; Approved means permitted; Fulfilled means delivered; Rejected means not permitted. Read the decision note.

## Choose the correct accreditation area
Role: USER
Path: User Portal > Accreditation > AACCUP / ISO
AACCUP and ISO pages identify the area number, name, campus, college, and audience. Requirements become visible only after an administrator attaches a template to the area.

1. Open Accreditation and select AACCUP or ISO 21001:2025.
2. Select College-wide for requirements shared across the college, or Program areas for your own program.
3. Choose an area tab and check its area number and name.
4. Check Applies to and the reporting cycle before selecting a requirement.
5. Read the required indicator, description, upload rules, and current submission status.

Remember: If no requirements appear, an active template may not be attached or your account may be outside the area scope. Ask an administrator to check your campus, college, and program.

## Submit accreditation evidence
Role: USER
Path: Accreditation > Requirement > Submit
An evidence submission links a file to a specific requirement. The application validates the file against the configured upload rules.

1. Select Submit under the correct area and requirement.
2. Check the requirement code, area number, and program in the Submit Evidence dialog.
3. Upload a file, or select Choose from My Documents to use an existing document.
4. Review Document Title and add Remarks when needed. Follow the allowed file type and other rules.
5. Scroll down in the dialog if needed. Select Upload and Submit when enabled, wait for confirmation, and check My Submissions.

Remember: Uploading to My Documents alone does not place evidence in the review queue. The file must also be submitted to its requirement.

## Submissions, revisions, and Unsubmit
Role: USER
Path: Accreditation > My Submissions
My Submissions lists your evidence and review results. Choose the correct AACCUP or ISO set and apply filters as needed.

1. Open My Submissions and check the area and status of each document.
2. Pending: awaiting review. Approved: accepted. Returned: revision required. Rejected: evidence not accepted.
3. When a correction is needed, read the remarks and submit suitable revised evidence from the area or task.
4. When Unsubmit is available, open it and confirm Unsubmit evidence to withdraw the pending or returned record.
5. After withdrawal, the file remains in My Documents and can be used again.

Remember: Approved evidence cannot be unsubmitted. A historical returned row and a current approved row are separate submission records.

## Tasks and deadlines
Role: USER
Path: Accreditation > My Tasks
A task is an assigned work item for an area. Creating a requirement template does not automatically create or assign tasks.

1. Open My Tasks and select the correct accreditation set.
2. Read the task title, area, priority, due date, and required evidence.
3. Use available status actions to start or update the work.
4. When Submit or Resubmit is available, open it and follow the evidence dialog.
5. Check the approved evidence count and reviewer feedback before treating the requirement as complete.

Remember: Shared area progress represents the group; personal submission history is separate. Check each task deadline. Screenshots contain example records, so dates and counts may differ from your account.

## Report an issue with an attachment
Role: USER / ADMIN / ROOT
Path: Sidebar > Bug Report
Use Bug Report to describe a reproducible problem and attach a screenshot or supporting file.

1. Open Bug Report or Bug Reports.
2. Select the Affected tab. Describe the steps, actual behavior, and expected result.
3. Select Attach file to include a screenshot or supporting document.
4. Use a PNG, JPG, WebP, or PDF file up to 5 MB. Check the selected filename.
5. Select Submit report and wait for confirmation.

Remember: Do not include passwords in the report or screenshot. The attachment supports the issue report; it is not accreditation evidence.

## Admin: campus, college, and audience
Role: ADMIN / ROOT
Path: Admin > Accreditation > Campus > College
AACCUP and ISO use the same location flow. Select the organization before creating or managing areas.

1. Open Accreditation and select AACCUP or ISO 21001:2025.
2. Select a Campus card, then a College card.
3. In the college workspace, select College-wide or By program.
4. For By program, select the program before creating or opening an area.
5. Use the breadcrumb to return. Check Applies to so the area has the intended audience.

Remember: College-wide areas require the matching campus and college. Program areas require the matching program. A template library entry alone does not assign requirements to users.

## Admin: create and edit an area
Role: ADMIN / ROOT
Path: Admin > Accreditation workspace > Add Area
A new area inherits the location selected in the college or program workspace. Attach its requirement template inside the area afterward.

1. Select the campus, college, and College-wide or program audience first.
2. Select Add Area and enter the Area name.
3. Expand Optional details when a description or another available setting is needed.
4. Select Create area, then open the new card.
5. Use Edit on the card or detail page for corrections. Use Archive only when the area is no longer in active use.

Remember: Check the location before saving. Avoid duplicate areas for the same audience and accreditation set.

## Admin: attach a requirement template
Role: ADMIN / ROOT
Path: Area detail > Requirements
Area attachment connects the Root Requirement Builder to the user portal. Requirements become available to scoped users after this explicit step.

1. Open an area card and select its Requirements tab.
2. Find the Requirement template control.
3. Select an active template for the correct AACCUP or ISO set.
4. Select Apply to area. Check the resulting requirements and document codes in the list.
5. To replace the attachment, first select Remove template, then choose the replacement.

Remember: Removing the attachment preserves submission history. Task creation is separate; attaching a template does not automatically assign work.

## Admin: review Pending evidence
Role: ADMIN / ROOT
Path: Admin > Accreditation > Submissions
Only Pending records show action buttons in submission review. Double-click a non-pending record to read it.

1. Open Submissions and select the set, area, program, and Pending filter as needed.
2. Use View or Download to inspect the actual document and the requirement it addresses.
3. Select Approve when the evidence is sufficient and correct.
4. Select Return when changes are needed; enter a specific reason and an optional reference attachment.
5. Select Reject when the evidence is unacceptable. Wait for the refreshed status and check the result or notification.

Remember: The presence of a file is not enough for approval. Check the area, version, reporting period, completeness, and reviewer remarks.

## Admin: document requests and access
Role: ADMIN / ROOT
Path: Admin > Requests
Requests manages document-access or issuance requests. Read the requester, files, and justification before deciding.

1. Open Requests and locate a record using search or the status filter.
2. Check the requested documents and the requester's purpose.
3. Select Approve for a legitimate request.
4. Select Reject and provide a reason when access should not be granted.
5. Check the final status and related delivery or access result.

Remember: Request approval and accreditation approval are different decisions. Approving access does not approve an evidence requirement.

## Admin: accounts and organization scope
Role: ADMIN / ROOT
Path: Admin > User Management
Roles control available functions. Campus, college, and program assignments help determine the correct accreditation audience.

1. Open User Management and locate the account.
2. Use the available add or invite action for a new account.
3. Assign the correct role, campus, college, and program.
4. Use View and Actions for available account operations and status management.
5. If a user cannot see an area, check the organization assignment and account status first.

Remember: There are 20 active presentation accounts. Demo personnel are fictional. Account credentials are provided in a separate CSV, not in this manual.

## Audit history and October reporting
Role: ADMIN / ROOT
Path: Admin > Audit Logs / Root > System Audit
Audit Logs identifies the actor, action, module, timestamp, and result. Date presets are relative to the actual current date.

1. Open Audit Logs. Select Submissions, Requests, or Login Activity as needed.
2. Use search and action/status filters. Select Reset to clear the current filters.
3. Open available record details to inspect the action and target.
4. Select Export CSV and choose the reporting period in the date fields. For example, October 1-31 for an October report.
5. Check the time zone and selected date range before sharing the exported report.

Remember: The 1,830 October audit entries are generated presentation samples with synthetic metadata. They are not evidence of real institutional activity.

## Root: overview and organization
Role: ROOT
Path: Root Console > Platform Overview / Organization
The Root Console controls platform configuration. Organization supplies the campus, college, and program choices used in accreditation setup.

1. Open Platform Overview for system summaries and storage counts.
2. In Organization, select the campus, college, office, or program tab.
3. Create or edit a record with a clear name, stable code, and correct parent organization.
4. Review the hierarchy and available history before archiving or restoring records.
5. Keep codes stable and avoid duplicating existing organization records.

Remember: The existing campus, college, and program setup was preserved during the presentation reset. These configuration pages are for Root, not the normal faculty workflow.

## Root: reusable folder structures
Role: ROOT
Path: Root Console > Folder Builder
Folder Builder maintains reusable folder trees and scope assignments. It does not automatically move existing user files.

1. Select Create Template or an existing template.
2. Enter its name, code, description, and status.
3. Use Add root folder and node Actions to create, nest, or move folder nodes.
4. Review the tree and preview, then open Assignments.
5. Set an available target scope. Use Versions and History to review changes and rollback options.

Remember: Physical folders in My Documents and the folder template tree are separate records. Maintain the correct assignment for repository provisioning.

## Root: author requirement templates
Role: ROOT
Path: Root Console > Requirement Builder
Requirement Builder defines versioned checklists and evidence rules. A template remains a library entry until an administrator attaches it to an area.

1. Select New Template or an existing template from the library.
2. Set its name, code, accreditation set, and description.
3. Add grouping sections and required document nodes. Configure codes, descriptions, required states, and order.
4. Use Preview to inspect the structure and completeness before making the template Active.
5. An administrator must attach the active template to the actual area. Use History or Versions to review changes.

Remember: Edits to an active template are versioned and may affect attached areas. Review those areas before saving structural changes.

## Root: upload rules and version history
Role: ROOT
Path: Requirement Builder > Node Actions > Validation rules
Validation rules define which evidence files are acceptable. Depending on configuration, they produce blocking errors or advisory warnings.

1. Open Actions on a requirement node and select Validation rules.
2. Choose what to validate: file type, size, or another available rule.
3. Set the allowed values and choose whether a mismatch blocks the upload or shows a warning.
4. Provide a clear message that helps the user, and keep the rule enabled.
5. Scroll within the dialog and save the rule. Review Preview and version history, and test a suitable file before wider use.

Remember: Configured rules run during upload preflight and submission. The presentation templates include a PDF file-type rule.

## Root: setup, settings, and access controls
Role: ROOT
Path: Root Console > Setup Wizard / Configuration Engine
The six visible setup stages are Platform, Organization, Folders, Requirements, Administrators, and Summary. Workflow Builder and Form Builder are removed from this build.

1. Use Setup Wizard for guided configuration. Select Next or Previous and Save Progress as needed.
2. In Platform, check identity, academic year, timezone, and logo. Select Save Platform Info to save changes.
3. In Configuration Engine, use Edit and History for versioned settings such as upload policy.
4. In Roles & Permissions, review only the permissions required by each role.
5. Use Storage Maintenance and System Audit for system checks. Review the effects of maintenance actions before running them.

Remember: The former /root-workflow-builder and /root-form-builder links redirect to the Root overview. Neither module is part of the current manual workflow.
