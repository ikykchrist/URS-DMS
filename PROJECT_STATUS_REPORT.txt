ARCHITECTURE
------------
Layered, modular monolith. Backend = Express + Prisma + PostgreSQL + MinIO.
Frontend = Vite + React + TypeScript + Tailwind. Every feature module follows
the pattern: routes -> controller -> service -> repository -> Prisma. RBAC is
permission-driven (no role-name hardcoding). Error envelope is a single global
error handler. CORS, helmet, rate-limit, JWT auth, and request-context are
mounted as middlewares.

DOCKER STATUS
-------------
docker-compose.yml defines postgres 16, MinIO latest, pgAdmin 4, and the
server container. Postgres + MinIO have healthchecks; server has a
wget-based healthcheck on /api/v1/health. Volumes: urs-postgres-data,
urs-minio-data, urs-pgadmin-data, urs-server-logs. Network: urs-net (bridge).
The server Dockerfile is multi-stage (deps -> build -> runtime), runs as
non-root, Alpine + OpenSSL for Prisma. entrypoint.sh runs
prisma migrate deploy + prisma seed before starting the app.


POSTGRESQL STATUS
-----------------
Configured via DATABASE_URL env (validated by Zod on boot). Connection pooling
via Prisma's default. Container healthchecked with pg_isready. Init script
docker/postgres/init.sql exists. One consolidated migration
20260815000000_init (Sprint 2+3) is applied at boot.


PRISMA STATUS
-------------
schema.prisma declares 12 models (Role, Permission, RolePermission, User,
Session, AuditLog, Department, Folder, Document, DocumentVersion,
DocumentTag, DocumentShare, DocumentRequest). Wait - actually 13 models if
you count Department separately. Client is generated for
native + linux-musl-openssl-3.0.x. Seed is idempotent and re-runnable safely.


MINIO STATUS
------------
server/src/lib/storage.ts provides: singleton client, ensureBucket() 
(auto-creates bucket on first boot - wired into server.ts), presignUpload,
presignDownload, statObject, deleteObject, getObjectStream,
publicDownloadUrl, objectKeyFor. Object-key format:
documents/{documentId}/v{versionNumber}/{safe-filename}. Public endpoint
overrides supported. Health route probes MinIO via ensureBucket().


AUTHENTICATION STATUS
---------------------
JWT access (15m) + refresh (7d) tokens, argon2id password hashing.
authenticate middleware verifies access token, checks session is active,
loads user + permissions into req.auth. Refresh-token rotation with reuse
detection. Login lockout (5 attempts -> 15 min lock). Cookie + Bearer
support. Password change endpoint exists. ALL Sprint 2 endpoints functional.


RBAC STATUS
-----------
Catalog in server/src/modules/permissions/permissions.constants.ts lists
~22 codes across modules: users.*, documents.*, folders.*, departments.*,
request.*, audit.read, settings.manage, repository.manage, aaccup.manage,
storage.manage. Default role matrix binds 6 roles (ADMINISTRATOR,
QUALITY_ASSURANCE_OFFICER, DEPARTMENT_COORDINATOR, FACULTY, STAFF,
READ_ONLY). requirePermission(...codes) middleware is DB-backed, dynamic,
and writes PERMISSION_DENIED audit entries. No `if (role === "admin")`
anywhere in the backend.

SECTION 9 — ARCHITECT NOTES
================================================================================

WHAT MUST NOT CHANGE
--------------------

1. Permission-driven RBAC. The codebase deliberately avoids
   if (role === "admin"). Every authorization check goes through
   requirePermission(...) or in-service permission lookups. New modules must
   follow this pattern. Adding a new permission = one entry in
   permissions.constants.ts and (optionally) a binding in roles.constants.ts.

2. Layered module pattern. Every feature = types.ts, validator.ts,
   repository.ts, service.ts, controller.ts, routes.ts. No exceptions, no
   shortcuts. The Sprint 5 plan above adheres to this.

3. Standard response envelope. All endpoints return {success:true,data} or
   {success:true,data,meta} for paginated lists. Errors go through ApiError
   subclasses -> errorHandler.ts. Do not return raw arrays or hand-roll
   error JSON.

4. Zod everywhere on input. Body / query / params all run through
   validateBody / validateQuery / validateParams. Validators live next to
   the module that owns them.

5. Audit on every mutation. Use writeAudit() from
   modules/audit/audit.service.ts. Action codes are constants in
   config/constants.ts. The middlewares (authorize.ts) write their own
   PERMISSION_DENIED entries directly - that's the only exception.

6. Prisma migration discipline. Never edit an applied migration; add a new
   one. The current setup uses a single consolidated init migration
   20260815000000_init; future migrations are additive and idempotent.

7. Idempotent seed. prisma/seed.ts upserts permissions, roles,
   role-permissions, and the bootstrap admin. Safe to re-run on every boot.

8. Soft delete by default. All business entities (User, Document, Folder,
   Department) have deletedAt. Reads filter on deletedAt: null unless
   explicitly overridden. Hard delete is a separate, audited operation.

9. Env-driven config. Every configurable value comes from env.ts (validated
   at boot). New env vars must extend the Zod schema; missing vars fail the
   boot.

10. Docker + compose as the deployment contract. docker-compose.yml and
    server/Dockerfile together define what runs in production. Don't
    introduce host-only paths or system dependencies.

11. Frontend design language is locked. URS-DMS UNIVERSAL DEVELOPMENT RULES.txt
    in the repo root is the source of truth. Reuse existing components
    (Button, Card, Dialog, Badge, EmptyState, Skeleton, Tabs, Pagination,
    Table, etc.) instead of inventing new ones.

12. Sprint discipline. Each sprint ships one self-contained capability.
    Sprint 1: foundation. Sprint 2: auth + users + RBAC. Sprint 3: documents
    + folders + dedupe/verify. Sprint 4: requests workflow. Sprint 5
    (proposed): departments + audit. Sprint 6+: AACCUP, notifications, etc.
    Don't reorder.


KEY DESIGN DECISIONS WORTH KNOWING
----------------------------------

- No role-name hardcoding. isManager(actor) is implemented as
  actor.permissions.includes("documents.delete") (or analogous permission
  code), not as a check against actor.roleName === "ADMINISTRATOR". This is
  the single most important rule to preserve.

- MinIO via presigned URLs. The backend never buffers file bytes. Uploads
  and downloads go browser -> MinIO via signed URLs. Server-side
  getObjectStream exists but is unused - preferred for future range-request
  / proxy-download features.

- Document version identity. Each new version mints a new DocumentVersion
  row with a fresh UUID; the object key embeds v{versionNumber}/{filename}
  so physical objects are never overwritten. Document.currentVersionId is
  the pointer; it's @unique because one current per document.

- Checksum verification. Sprint 3 ships checksum dedupe (per-document) and
  etag verify via a separate POST /:id/versions/:versionId/verify endpoint.
  The actual byte-level SHA-256 is not re-hashed server-side (etag is not
  SHA-256); this is documented in the service code.

- Folder cascade soft-delete. The Prisma onDelete: Cascade only fires on
  HARD delete. Service explicitly traverses the subtree and stamps
  deletedAt on each child during soft delete. Same for restore.

- Client mock layer coexists. Every Sprint-N backend module ships with a
  client adapter in client/src/services/api.ts. The localStorage mock
  layer remains in place for features that haven't been wired yet (audit,
  departments, AACCUP, notifications). This is per Rule #2 (do not break
  the system).

- /requests response envelope. Currently returns a bare array (deviation
  from convention); flagged as Issue #5. Fix it next pass.

- Document upload is a two-step flow. POST /documents creates the metadata
  row and returns a presigned PUT URL for the FIRST version - but does not
  create the DocumentVersion row until POST /documents/:id/version is
  called. Document this clearly in API docs.
